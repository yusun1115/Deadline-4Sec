# 1. Game Overview

## 1.1 Title

**Deadline:4초**

## 1.2 Genre

- 3D Action Runner
- Arcade Action
- Score Attack
- Endless Run

## 1.3 Core Concept

플레이어에게 주어진 생존 시간은 단 **4초**다.

4초 동안 아무런 위험 행동을 하지 않으면 플레이어는 사망한다.

하지만 다음 행동에 성공하면 생존 시간이 다시 `4.00초`로 초기화된다.

- Enemy Kill
- Air Enemy Kill
- Stomp Kill
- Ground Slam Kill
- Near Miss

따라서 이 게임은 일반적인 러너 게임처럼 위험을 피하는 것이 아니라,

> **살아남기 위해 계속 위험한 행동을 해야 하는 게임**

을 목표로 한다.

Core Phrase:

> **Risk to Live.**
>
> **살아남기 위해 위험해져라.**

---

# 2. Core Design Pillars

게임의 모든 신규 기능은 다음 원칙을 해치지 않아야 한다.

## 2.1 Movement = Attack

별도의 Attack Button을 만들지 않는다.

플레이어의 이동 행동 자체가 공격 행동이다.

- Left / Right → 이동 + Lane Attack
- Jump → 회피 / Jump Attack
- Air Jump → Homing Attack
- Slide → Slide / Slide Attack
- Air Slide Input → Fast Fall
- High Altitude Fast Fall → Ground Slam

---

## 2.2 Constant Pressure

플레이어는 항상 4초 Timer 때문에 행동해야 한다.

안전한 위치에서 아무 행동도 하지 않는 플레이를 허용하지 않는다.

---

## 2.3 Risk = Reward

위험한 플레이일수록 생존과 점수 면에서 보상을 얻는다.

예:

- Enemy Kill
- Near Miss
- Air Combo
- Stomp
- Ground Slam

---

## 2.4 Continuous Action

게임의 액션은 끊기지 않고 연결되어야 한다.

예:

```text
Lane Attack
→ Jump
→ Air Homing
→ Air Homing
→ Fast Fall
→ Stomp
→ Bounce
→ Air Homing
````

또는:

```text
Air Homing Combo
→ High Altitude
→ Ground Slam
→ AOE Kill
→ Strong Bounce
→ Air Homing
```

## Planned

Title Screen 구성:

```text

Tap to start

[SETTINGS]

타이틀에 Start/Play 및 Tutorial 버튼은 두지 않는다. 설정 버튼을 제외한 타이틀 화면을 누르면 시작한다. 완료/스킵 기록이 없으면 첫 시작은 튜토리얼로 이동하고, 완료하거나 스킵한 이후에는 일반 런의 Ready?→Go!로 이동한다. 완료/스킵 기록은 앱 재실행 후에도 유지한다.

Settings에서는 사운드/진동 아래에 Tutorial 버튼을 두어 완료/스킵 이후에도 연습을 다시 시작할 수 있게 한다.

타이틀 UI는 씬에 저장된 `Canvas/TitlePanel` 오브젝트로 구성한다. Play를 실행하지 않은 상태에서도 Hierarchy와 Inspector에서 로고·프레임(또는 제목·부제), 탭 시작 문구, 설정 버튼, 배경 색/이미지, 위치와 크기를 코드 수정 없이 편집하고 저장할 수 있어야 한다. 버튼 기능은 Inspector의 On Click으로 연결한다. 실행 중 타이틀을 새로 생성하거나 저장한 외형/Canvas 설정을 덮어쓰지 않는다. Settings와 결과의 Main Menu 버튼도 씬에 저장한다. 게임 폰트는 GFCRedSpirit-Bold 규칙을 유지한다.

추후 추가 가능:

* Player character animation
* Background animation
* Best Score 표시
* Version 표시

# 6. Run Start Flow

Game Start를 누르면 첫 패턴을 미리 생성하고 캐릭터가 앞으로 달리는 시작 연출을 재생한다.

State:

```text
Ready? (Forward Run + Camera Transition)
↓
Go! / Playing
```

3·2·1 카운트다운은 사용하지 않는다. `Ready?` 동안 카메라가 캐릭터 측면에서 기존 인게임 위치/방향으로 부드럽게 이동한다. 캐릭터는 점차 인게임 전진 속도로 가속하고 첫 장애물/적 패턴은 이미 앞에 보여야 한다. GO에서 패턴을 갑자기 생성하거나 타이틀 화면으로 전환하지 않는다.

시작 연출의 이동은 점수·거리·런 시간·속도 상승에 포함하지 않는다. 게임 입력과 생존 타이머는 꺼져 있고, 첫 위협은 Go 이후 최소 1.5초의 접근 시간을 확보한다. 첫 보상 기회는 4초 생존 시간 안에 도달할 수 있어야 한다.

카메라가 인게임 뷰에 도달하고 `Go!`가 나오는 순간:

* Player Auto Run 활성화
* Player Input 활성화
* Survival Timer = 4.00
* Run Time 시작
* Score 활성화
* Distance 측정 시작
* Speed Progression 시작
* 미리 보이는 패턴을 유지하며 PatternSpawner 스트리밍 활성화

# 7. Player Controls

## 7.1 Mobile

```text

→ Move Left
→ Lane Attack

Swipe Right
→ Move Right
→ Lane Attack

Swipe Up
→ Ground: Jump
→ Air: Homing Attack

Swipe Down

예:

```text
A / Left Arrow
→ Left

D / Right Arrow
→ Right

Space / W / Up Arrow
→ Jump

S / Down Arrow
→ Slide / Fast Fall
```

# 9. Basic Movement

Player는 자동으로 전진한다.

Player가 직접 Forward 입력을 하지 않는다.

Player Actions:

* Lane Left
* Lane Right
* Jump
* Slide

공중에서도 Left / Right 이동 가능.

불필요한 Action Lock을 최소화한다.

게임의 조작감은:

* Fast
* Fluid
* Responsive

해야 한다.

---

# 10. Survival Timer

Player 생존 시간:

```text
4.00 seconds
```

Timer는 계속 감소한다.

```text
Timer <= 0
→ Game Over
```

Timer Reset 조건:

* Enemy Kill
* Air Enemy Kill
* Stomp Kill
* Ground Slam Kill
* Near Miss

Reset:

```text
Timer = 4.00
```

Timer 최대값을 4초 이상 누적시키지 않는다.

---

# 11. Ground Enemy Rules

Ground Enemy는 단순 Collider가 아니라 공격 가능한 적이다.

Enemy에는:

```text
Body Collider
Attack Zone
```

이 존재한다.

---

## 11.1 Front Enemy

Player 정면에 Enemy가 있는 경우:

### Normal Collision

```text
Player → Enemy
→ Game Over
```

### Jump Over Enemy

정면 Enemy의 머리 위를 Jump로 억지로 넘어가려는 경우:

```text
Enemy Attack
→ Game Over
```

### Forward Slide

Enemy 밑으로 Slide해서 통과하려는 경우:

```text
Enemy Attack
→ Game Over
```

즉 정면 Enemy는 단순 Jump / Slide로 회피할 수 없다.

---

# 12. Side Enemy Rules

Player 옆 Lane에 Enemy가 있는 경우:

## Enemy 방향으로 Lane Move

```text
Lane Move
→ Lane Attack
→ Enemy Kill
→ Timer Reset
```

## Enemy 무시

Player가 Enemy 옆을 아무 행동 없이 지나감:

```text
Enemy Side Attack
→ Game Over
```

## Forward Slide

Enemy 옆에서 단순 Slide로 통과:

```text
Enemy Attack
→ Game Over
```

## Jump Over Side Enemy

Player가 충분히 높은 위치에서 Enemy 옆을 Jump로 지나가면:

```text
Safe
```

Enemy의 실제 공격 높이보다 Player가 위에 있기 때문이다.

---

# 13. Enemy Kill Priority

하나의 Enemy가 같은 Frame에 Kill과 Game Over를 동시에 발생시키면 안 된다.

Priority:

```text
1. Enemy already dead?
   → Ignore

2. Valid Stomp?
   → Kill

3. Valid Homing Attack?
   → Kill

4. Valid Lane / Player Attack?
   → Kill

5. Enemy Attack Zone?
   → Game Over

6. Normal Body Collision?
   → Game Over
```

Enemy Kill 순간:

```text
isDead = true
```

Attack Zone을 즉시 비활성화한다.

---

# 14. Air Enemy

Air Enemy는 Player 위쪽 / 공중에 배치된다.

Air Enemy 역시 Player를 공격한다.

Player가 Air Enemy 밑을 아무 대응 없이 지나갈 경우:

```text
Air Enemy Down Attack
→ Game Over
```

Air Enemy는 Down Attack Zone을 가진다.

---

# 15. Air Homing Attack

Player가 공중 상태에서 Jump 입력을 하면:

```text
Find Air Enemy
→ Homing Dash
→ Enemy Kill
→ Timer Reset
→ Small Bounce
```

Homing은 가장 적합한 Air Enemy를 찾는다.

Homing 느낌:

```text
Player
→ Magnetic Pull
→ Enemy
```

Player가 빠르게 Enemy에게 빨려 들어가는 느낌이어야 한다.

---

# 16. Air Combo

Air Enemy Kill 이후 Player는 작은 Upward Bounce를 받는다.

이후 다시 Jump 입력:

```text
Next Air Enemy
→ Homing
→ Kill
→ Bounce
```

반복 가능.

예:

```text
Enemy 1
→ Enemy 2
→ Enemy 3
→ Enemy 4
```

Air Enemy를 계단 형태로 배치하면 Player가 점점 위로 올라갈 수 있다.

---

# 17. Fast Fall

Air + Swipe Down:

```text
Fast Fall
```

공중 Slide는 존재하지 않는다.

즉:

```text
Air + Down Input
≠ Slide
```

항상 빠른 낙하 행동이다.

---

# 18. Stomp

Fast Fall 중 Enemy 머리 위에 도달하면:

```text
Stomp Attack
→ Enemy Kill
→ Timer Reset
→ Strong Bounce
```

Stomp 판정은 너무 정확한 위치 입력을 요구하지 않는다.

Player가:

* Airborne
* Falling Down
* Above Enemy

상태라면 어느 정도 넓게 판정한다.

고공 슬램 발동 조건을 충족한 상태여도 적 머리 접촉은 항상 Stomp다. 빠른 낙하 경로를 연속 검사해 발이 머리 윗면에 닿는 위치에서 하강을 멈추고 처치·타이머 초기화·바운스한다. 한 프레임에 머리나 몸통을 관통한 뒤 아래에서 튀어 오르는 동작은 허용하지 않는다.

---

# 19. Ground Slam

Ground Slam은 적/장애물이 없는 맨 바닥에 착지해 충격파를 일으키는 고공 낙하 행동이다.

Player가 Air Combo 등을 통해 충분히 높은 곳까지 올라간 상태에서:

```text
Swipe Down
```

하면 High Ground Slam이 발동한다.

---

## 19.1 Ground Slam Requirement

단순 World Y가 아닌:

```text
Player ↔ Ground Distance
```

를 기준으로 한다.

조건:

```text
Ground Distance >= groundSlamMinHeight
```

---

## 19.2 Ground Slam Flow

```text
High Altitude
↓
Swipe Down
↓
Ground Slam
↓
Fast Descent
↓
Ground Impact
↓
AOE Attack
↓
Strong Bounce
```

낙하 도중 적 머리에 먼저 닿으면 Ground Slam은 취소되고 Stomp 처치와 바운스로 전환한다. 이때 지면 충격파나 주변 적 광역 처치는 발생하지 않는다. 장애물 윗면 착지는 안전하지만 Ground Slam 충격파를 발생시키지 않는다. 슬램 상태만으로 적 몸통/공격 범위를 통과하는 무적 판정은 없다.

---

## 19.3 Ground Slam AOE

Ground Impact 지점을 기준으로 범위 공격을 한다.

예:

```text
Physics.OverlapSphere
```

Target:

* Enemy only

Do NOT target:

* Floor
* Obstacle
* Near Miss Zone

Ground Slam으로 여러 Enemy를 처치할 수 있다.

---

## 19.4 Ground Slam Timer

한 Ground Slam에서 Enemy가 여러 마리 죽더라도:

```text
Timer Reset
```

은 한 번만 실행한다.

Score / Combo는 Kill 수에 따라 각각 처리할 수 있다.

---

## 19.5 Ground Slam Bounce

Ground Slam 후:

```text
Strong Bounce
```

를 발생시킨다.

일반 Stomp보다 강한 Bounce를 기본 방향으로 한다.

이를 이용해:

```text
Ground Slam
→ Bounce
→ Homing
```

으로 다시 공중 전투에 진입할 수 있다.

---

# 20. Obstacles

Enemy와 Obstacle은 완전히 다른 Entity이다.

Obstacle은 공격하거나 파괴하지 않는다.

Obstacle의 앞면이나 옆면에 충돌하면:

```text
→ Game Over
```

위에서 내려와 Obstacle 윗면에 착지한 경우에는 밟고 지나갈 수 있다.
윗면 착지는 Game Over가 아니다.

Player Attack 상태라도 Obstacle은 파괴되지 않는다.

---

# 21. Basic Obstacle Types

## Lane Obstacle

Left / Right 이동으로 회피.

## Jump Obstacle

Jump로 넘는다.

## Slide Obstacle

Slide로 통과한다.

---

# 22. Near Miss

Obstacle에는 실제 Collider보다 넓은:

```text
Near Miss Zone
```

이 존재한다.

Near Miss Zone에 들어갔다고 즉시 성공 처리하지 않는다.

Flow:

```text
Enter Near Miss Zone
→ Near Miss Candidate

Player passes obstacle
AND
No physical contact with obstacle

→ Near Miss Success
```

Near Miss Success:

```text
Timer Reset = 4.00
Score
Combo
Feedback
```

Obstacle의 앞면/옆면 충돌은 Game Over이며 Near Miss는 실패한다.
안전한 윗면 착지도 실제 접촉이므로 Near Miss로 인정하지 않는다.

한 장애물당 Near Miss는 한 번만 발생한다.

---

# 23. Score

현재 기본 Score 예시:

```text
Ground Enemy Kill = 100
Air Enemy Kill    = 100
Stomp Kill        = 150
Near Miss         = 150
Ground Slam Kill  = configurable
```

추후 밸런싱 가능.

# 24. Combo

다음 행동 성공 시 Combo 증가:

* Enemy Kill
* Air Kill
* Stomp
* Ground Slam Kill
* Near Miss

Combo Timeout:

약 2~3초.

Survival Timer와 Combo Timer는 서로 완전히 독립적이다.

---

## Combo Multiplier

Example:

```text
Combo 0–4
→ x1

Combo 5–9
→ x2

Combo 10–19
→ x3

Combo 20+
→ x4
```

Multiplier는 Score에만 영향을 준다.

Survival Timer에는 영향을 주지 않는다.

---

# 25. Distance

Forward Direction으로 이동한 거리만 계산한다.

Y축 이동이나 Lane 이동 때문에 Distance가 증가해서는 안 된다.

---

# 26. Speed Progression

Run Time에 따라 Auto Run Speed가 증가한다.

Variables:

```text
baseForwardSpeed
maxForwardSpeed
speedIncreasePerSecond
```

변경되는 것은 Auto Forward Speed뿐이다.

다음 값에는 영향을 주지 않는다.

* Homing Speed
* Fast Fall Speed
* Ground Slam Speed
* Jump Power
* Bounce Power
* Lane Speed

---

# 27. Pattern-Based Level Generation

완전 Random Generation은 사용하지 않는다.

이유:

Random 배치는:

* Impossible Jump
* Unavoidable Enemy
* 4초 이상 Action Opportunity 없음

등의 문제가 발생할 수 있다.

따라서 Pattern 기반 생성 방식을 사용한다.

---

# 28. Pattern Types

Example:

```text
Pattern_A_LaneAttack

Pattern_B_JumpObstacle

Pattern_C_AirCombo

Pattern_D_Stomp

Pattern_E_MixedRisk
```

---

# 29. Pattern Difficulty

Difficulty:

```text
Easy
Medium
Hard
```

Example:

```text
0–20 sec
→ Easy 중심

20–45 sec
→ Easy + Medium

45 sec+
→ Medium + Hard
```

값은 Inspector에서 조절 가능하게 한다.

Medium/Hard 선택 해금은 실제 Run Time을 기준으로 한다. 앞서 생성하는
패턴은 예상 도착 시간도 검사해 45초 이후 구간에 Easy를 새로 배치하지 않는다.
호밍으로 이동 시간이 줄어도 해금 전 Medium/Hard가 먼저 나타나서는 안 된다.

---

# 30. Pattern Category

Pattern Category 예:

```text
GroundCombat
AirCombat
Obstacle
Stomp
Mixed
```

같은 Category가 지나치게 반복되지 않도록 한다.

---

# 31. Pattern Rules

PatternSpawner는 다음 규칙을 가진다.

* 같은 Pattern 연속 등장 금지
* 동일 Category 과도한 반복 방지
* Difficulty 조건에 맞는 Pattern만 선택
* 4초 이상 아무 Action Opportunity가 없는 구간 금지

필요하면 Fixed Seed Debug를 지원한다.

---

# 32. Pattern Entry / Exit State

Pattern은 Player 상태를 고려한다.

Example:

```text
Ground
Air
Any
```

Impossible transition을 방지한다.

예:

```text
High Air Combo
→ Forced Ground Slide
```

같은 불가능한 연결을 생성하지 않는다.

---

# 33. Game States

Recommended:

```text
Title / Settings
Ready (Ready? + Run Intro)
Playing

# 54. Tutorial

게임 조작이 단순하지만 각 입력의 의미가 상황에 따라 달라지므로 Tutorial이 필요하다.

Tutorial Sequence:

```text
1. Swipe Left / Right

2. Jump

3. Slide

4. Lane Attack

5. 4-second Timer

6. Near Miss

7. Air Homing

8. Fast Fall

9. Stomp

10. Ground Slam
```

Tutorial은 실제 Gameplay를 멈추고 긴 설명을 보여주기보다는 짧은 Interactive Tutorial을 목표로 한다.

최초 타이틀 탭으로 위 10단계를 연습한다. 이후에는 Settings의 Tutorial 버튼으로 언제든지 다시 시작할 수 있다. 각 단계는 실제 플레이 입력과 기존 적/장애물 판정을 사용하며, 안내에 해당하는 행동이 성공한 뒤 다음 단계로 진행한다. 실패하면 현재 단계부터 재시도한다.

튜토리얼 우측 상단에 Skip 버튼을 둔다. 누르면 `튜토리얼을 스킵하시겠습니까? (설정창에서 언제든지 튜토리얼을 다시 할 수 있습니다.)`를 예/아니오 버튼과 함께 보여준다. 확인창이 열린 동안 연습 시간·이동·입력·단계 진행을 멈춘다. 아니오는 현재 단계를 이어 하고, 예는 스킵 완료를 저장한 뒤 일반 런의 Ready?→Go!로 시작한다.

연습의 준비/성공 안내 중에는 타이머와 입력을 잠시 멈추고, 활성 연습 구간에서는 기존 4초 초기화·Stomp 머리 우선·맨 바닥 Slam·장애물 윗면 안전 규칙을 그대로 적용한다. 연습 점수는 최고 기록에 저장하지 않는다.

완료 화면의 Start Run은 새 일반 런의 Ready? 달리기/측면→인게임 카메라 연출→Go!로 연결한다. Menu는 Title로 돌아간다. 모든 안내와 버튼은 GFCRedSpirit-Bold 원본 폰트를 사용한다.

# 76. Final Development Principle

>

```

신규 기능을 추가할 때는 항상 다음 질문을 확인한다.

1. 이 기능이 4초 시스템을 강화하는가?
2. Player가 더 적극적으로 움직이게 만드는가?
3. 기존 Action Combo를 방해하지 않는가?
4. 모바일 Swipe로 쉽게 사용할 수 있는가?
5. 1인 개발 범위에서 관리 가능한가?

위 조건을 만족하지 않는 기능은 바로 구현하지 않고 먼저 설계를 검토한다.

```



> `먼저 SPEC.md와 현재 프로젝트 코드를 확인해. SPEC.md의 게임 규칙을 Source of Truth로 사용하되, 실제 구현 상태는 코드를 기준으로 판단해. 이미 정상 작동하는 기능을 불필요하게 다시 작성하지 말고 이번 요청에 필요한 최소 범위만 수정해.`

# 77. Coin / Power-Up / Upgrade 추가 규칙 (2026-09-28)

사용자가 제공한 `coin,item.txt`와 후속 요청을 반영한다. 아이템 레벨 업그레이드는 6종 아이템의 지속시간/효과만 조정하며, §62의 복잡한 능력치 Upgrade Tree와 별개인 소규모 시스템이다.

- 코인은 패턴 프리팹에 수동 배치한다. 획득 시 런 코인만 증가하며 점수·콤보·생존 타이머는 바뀌지 않는다. 게임 오버에서 런 코인을 보유 코인으로 한 번 정산한다. 보유 코인과 아이템 레벨은 영구 저장한다.
- 타이틀 화면 상단에 보유 코인을 표시한다. 하단의 `UPGRADES` 버튼을 누르면 Inspector에서 편집 가능한 업그레이드 화면으로 이동한다. 각 아이템의 현재 레벨/효과, 다음 레벨 효과, 비용, 구매 버튼을 표시한다.
- 모든 아이템은 Lv.1부터 Lv.7 MAX까지 업그레이드한다. 비용은 Lv.1→2부터 순서대로 `500 / 1000 / 2000 / 4000 / 8000 / 15000` 코인이다. 코인 부족·MAX에서는 레벨이나 코인이 바뀌지 않는다.
- 효과값 표의 순서는 Lv.1→Lv.7이다. 실제 조정값은 `Assets/Resources/PowerUps/PowerUpBalance.asset` 한 곳에서 편집한다.

Reaper Rush도 타이머가 0이면 사망한다. Time Heart 종료 시 최대 타이머는 다시 4초이고 남은 시간은 4초로 제한한다. 같은 아이템을 다시 먹으면 지속시간을 레벨값으로 갱신하고, 다른 종류는 동시에 활성화할 수 있다. 게임 오버/재시도 후 활성 효과와 런 코인은 초기화한다. 적 머리를 밟는 Stomp 우선순위, 맨 바닥 Slam, 장애물 윗면 안전 판정은 유지한다.
